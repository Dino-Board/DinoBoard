# Jaipur — AI API 接入文档

## 概览

- **game_id**：`jaipur`
- **玩家数**：2
- **范围**：只打**一轮**（不是规则书的三局两胜，多轮由接入方按轮重开会话）；0 号位先手
- **动作空间**：114（factored atoms，见下）；一个回合 = BGA 上的一次操作（拿 / 拿骆驼 / 卖 k 张 / 一次交换）
- **隐藏信息**：对手手牌的构成、牌堆的构成、面朝下奖励标记的面值（对手拿到的和堆里剩下的）
- **公开事件**：`goods_taken`、`goods_sold`、`trade_resolved`（都是公开事件，所有视角相同）

---

## 动作编码

货物类型 `g`：`0=钻石 1=黄金 2=白银 3=香料 4=布料 5=皮革`；交换付出时 `x=6` 表示骆驼。

| 范围 | 含义 |
|------|------|
| 0–5 | 从市场拿 1 张 `g` 类货物（手牌 < 7） |
| 6 | 拿走市场上全部骆驼 |
| 7–48 | 卖出 `k` 张 `g` 类货物：`7 + g*7 + (k−1)`，`k = 1..7`（钻石/黄金/白银 `k ≥ 2`；可以只卖一部分） |
| 49–78 | 交换·换入：从市场拿 `k` 张 `g` 类：`49 + g*5 + (k−1)` |
| 79–113 | 交换·付出：交出 `k` 张 `x` 类（`x=6` 为骆驼）：`79 + x*5 + (k−1)` |

交换按原子顺序提交：先按 `g` 升序给出全部换入原子，再按 `x` 升序给出付出原子（骆驼最后）。付出总数等于换入总数时交换结算并换手。规则只列出**一定能完成**的原子，所以交换一旦开始不会走进死路，也没有取消动作。交换中途 `current_player` 不变，已选的部分是公开的 `trade_take[6]` / `trade_give[7]`。

例：拿 2 张香料 + 1 张皮革，付 1 张白银 + 2 只骆驼 → `[49+3*5+1, 49+5*5+0, 79+2*5+0, 79+6*5+1]`。

---

## 随机性：没有预存的牌序

牌堆和奖励标记堆**都不保存顺序**：

- 牌堆是每类牌的张数 `deck_count[7]`（隐藏），抽牌是在抽的那一刻用调用方传入的 rng 按张数加权抽样。
- 每档奖励堆是每种面值的个数 `bonus_pile[3][3]`（隐藏），卖出 3/4/5+ 张时同样用 rng 加权抽一个。
- 因此任何 state（真值、会话、MCTS 模拟世界）里都不存在"下一张牌是什么"。真值对局可由 episode seed 复现（GT 的 step rng 由 seed 决定）；模拟世界用模拟自己的 rng，从 `randomize_unseen` 采样出的构成里抽。
- 规则在抽牌时会校验隐藏构成与公开张数一致；对一个没有经过 `randomize_unseen` 的观察者 state 直接执行抽牌动作会抛异常，而不是编造一张牌。

## 公开事件

| kind | payload | 何时发 |
|------|---------|--------|
| `goods_taken` | `{player, good_type, count}`（`count = 1`） | 动作 0–5 |
| `goods_sold` | `{player, good_type, count}` | 动作 7–48 |
| `trade_resolved` | `{player, take: [6 个张数], give: [7 个张数，最后一个是骆驼]}` | 交换结算的那个付出原子 |

事件只喂给 tracker。玩家自己抽到的奖励面值**不走事件**，而是作为 owner-only 的 state 槽位 `bonus_taken` 随快照下发给本人。

---

## 快照字段（schema）

全公开：`current_player`、`winner`、`terminal`、`plies`、`market_count[7]`（6 类货物 + 骆驼）、`deck_pos`（已抽张数，牌堆余量 = 55 − `deck_pos`）、`camel_count[2]`、`rupees[2]`（货物标记分 + 骆驼标记）、`value_tokens[6]`（各类货物标记剩余个数）、`bonus_tokens_3/4/5`（三档奖励堆剩余个数）、`camel_bonus_token`、`piles_exhausted`、`bonus_count[2][3]`、`goods_tokens_taken[2]`、`discard_count[6]`（已卖出弃掉的各类货物张数）、交换进行中的 `trade_take[6]` / `trade_give[7]`。

仅本人可见（owner-only）：`hand_count[p][6]`、`bonus_total[p]`、`bonus_taken[p][3][3]`（本人抽到的各档各面值个数）。

对双方都隐藏：`deck_count[7]`、`bonus_pile[3][3]`。

`get_state_dict()` 是真值侧的完整转储（含对手手牌、`deck_count`、`bonus_pile`），只用于 GT / 测试 / 本地前端，不要转发给对手。

## 初始观察与中途接入

`extract_initial_observation(seat)` 的 `tracker_init` 携带：

| key | 内容 |
|-----|------|
| `own_hand` | 本人 6 类货物张数 |
| `known` | 12 个整数：`[p*6+g]`，从公开动作可确定的玩家 p 手里 g 类货物张数下界 |

`known` 的推导：拿 1 张 `+1`；卖 k 张 `max(known, k) − k`；交换先扣付出（同卖出的规则）再加换入。`known` 是 tracker 的全部记忆，可以在**任意一步**取出：新会话用它初始化后，与从第 0 步开始逐步接收事件的会话信念完全一致。接入 BGA 时也可以直接从对局历史按上面的规则重算。

模拟世界中对手手牌：在下界之上把剩余张数均匀地从未见牌池补齐。对手正处在交换中途时，会重采样直到对手已选的前缀可以完成（最多 1000 次，失败抛异常）。

## 终局

- 三种货物标记堆取空，或补市场时牌堆不够 → 本轮结束。
- 骆驼多者 +5（相同则都不加）。
- 胜者：`rupees + bonus_total` 高者；相同比奖励标记个数；再相同比货物标记个数；仍相同为平局（`winner = -1`，双方价值 0）。
- 达到 `max_game_plies` 仍未结束：走 adjudicator，双方价值都是 −1（拖延惩罚，有意的非零和）。

---

## 常见踩坑

- **交换必须整笔提交**：BGA 上交换是一个请求；接入方要把 AI 给出的原子攒到结算那一步再一起执行，不能拿到第一个原子就下单。
- **`trade_resolved` 的数组长度固定**：`take` 6 个、`give` 7 个，经 JSON/Python 往返后仍要保持长度。
- **不要对观察者会话调用 `apply_action`**：观察者会话只通过 `apply_observation` 推进。
